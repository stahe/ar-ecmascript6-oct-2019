    11. البرمجة القائمة على الأحداث والوظائف غير المتزامنة

    الوظيفة غير المتزامنة هي وظيفة يتم تشغيلها دون انتظار النتيجة. عند انتهاء التنفيذ، تصدر الوظيفة غير المتزامنة حدثًا وتنقل نتيجتها عبره.

    هذا النمط من التشغيل مناسب تمامًا للتنفيذ داخل متصفح الويب. في الواقع، التطبيق الذي يتم تنفيذه داخل متصفح هو تطبيق قائم على الأحداث: يستجيب التطبيق للأحداث، التي يسببها المستخدم بشكل أساسي (النقرات، تحركات الماوس، كتابة النص، ...). تتواصل تطبيقات جافا سكريبت التي يتم تنفيذها داخل متصفح مع خدمات خارجية عبر بروتوكول HTTP. وظائف جافا سكريبت الأصلية HTTP هي وظائف غير متزامنة: يتم تشغيلها ويتم الإبلاغ عن استلام الرد من الخدمة الخارجية المطلوبة بواسطة حدث يُضاف إلى مجموعة الأحداث التي تديرها التطبيق.

    سيتم تنفيذ البرامج النصية التالية بواسطة [node.js] وليس بواسطة متصفح. كما أن [node.js] لديه أيضًا وضع تنفيذ حسب الحدث:

    • يستخدم [node.js]، مثل المتصفح، حلقة أحداث لتنفيذ البرنامج النصي؛
    • يُعد تنفيذ الكود الرئيسي للبرنامج النصي هو الحدث الأول الذي يتم تنفيذه؛
    • إذا أطلق هذا الكود الرئيسي مهام غير متزامنة، فإن التنفيذ يستمر حتى تنتهي هذه المهام غير المتزامنة. وتصدر هذه المهام حدثًا عند انتهائها. يتم وضع هذه الأحداث في قائمة انتظار في حلقة الأحداث؛
    • يجب أن يشترك البرنامج النصي الرئيسي في هذه الأحداث إذا أراد استرداد نتائج الإجراءات غير المتزامنة؛
    • لا ينتهي البرنامج النصي إلا بعد معالجة جميع الأحداث التي أصدرها؛

    11.1. البرنامج النصي [async-01]

    يوضح البرنامج النصي التالي سلوك برنامج نصي يتضمن إجراءً غير متزامن.

    
'use strict';

// الاستيرادات
import moment from 'moment';
import { sprintf } from 'sprintf-js';

// البداية
const débutScript = moment(Date.now());
console.log("[début du script],", heure());

// setTimeout يضبط مؤقتًا لمدة 1000 مللي ثانية (المعلمة الثانية) ويعيد على الفور رقم هذا المؤقت
// عندما ينتهي المؤقت من 1000 مللي ثانية، فإنه يصدر حدثًا يتم وضعه في قائمة انتظار وقت التشغيل
// عندما يتم معالجة الحدث بواسطة وقت التشغيل، يتم تنفيذ الدالة (المعلمة الأولى)
setTimeout(function () {
  // سيتم تنفيذ هذا الرمز عندما يصل المؤقت إلى القيمة 0
  console.log("[fin de l'action asynchrone setTimeout],", heure(débutScript));
}, 1000)

// سيتم عرضه قبل رسالة الدالة الداخلية للمؤقت
console.log("[fin du code principal du script],", heure(débutScript));

// أداة عرض الوقت والمدة
function heure(début) {
  // الوقت الحالي
  const now = moment(Date.now());
  // تنسيق الوقت
  let result = "heure=" + now.format("HH:mm:ss:SSS");
  // هل يجب حساب المدة؟
  if (début) {
    const durée = now - début;
    const milliseconds = durée % 1000;
    const seconds = Math.floor(durée / 1000);
    // تنسيق الوقت + المدة
    result = result + sprintf(", durée= %s seconde(s) et %s millisecondes", seconds, milliseconds);
  }
  // النتيجة
  return result;
}

      • السطر 17: يتم تفعيل مؤقت مدته 1000 مللي ثانية ويبدأ العد التنازلي حتى يصل لاحقًا إلى 0. تنتهي الدالة [setTimeout] بمجرد تهيئة المؤقت وبدء العد التنازلي. وهي لا تنتظر انتهاء هذا العد التنازلي. بل تُرجع رقمًا يُعرف المؤقت المستخدم، ثم ينتقل التنفيذ إلى التعليمات التالية، السطر 20. هنا، لا يتم استخدام نتيجة [setTimeout]؛
    • السطر 16: ستظهر هذه الرسالة في نهاية مهلة 1000 مللي ثانية للدالة [setTimeout]؛
    • السطران 15-16: سيتم تنفيذ الدالة f، المعلمة الأولى للدالة [setTimeout]، عند انتهاء مهلة 1000 مللي ثانية. ثم ستظهر الرسالة الموجودة في السطر 16؛

    • الأسطر 25-27: يتم حساب وتنسيق الوقت الحالي؛
    • السطر 29: إذا كان المعامل [début] موجودًا، فيجب حساب المدة؛

    • السطور 31-32: يتم تقسيم عدد الميلي ثانية هذا إلى ثوانٍ وميلي ثانية؛

    • تُرجع نتيجة على الفور، وهي في هذه الحالة رقم مؤقت، من خلال آلية الدوال المعتادة (return)؛

      • حدث يمكن تسميته [success] سيصدر عن المهمة غير المتزامنة التي نجحت في إنجاز ما كان عليها القيام به. ترتبط بيانات، وهي نتيجة المهمة، بالحدث الصادر؛
      • حدث يمكن تسميته [failure] والذي سيتم إصداره من قبل المهمة غير المتزامنة التي فشلت في إنجاز ما كان عليها القيام به. ترتبط بيانات، وهي عادةً كائن يصف الخطأ، بالحدث الذي تم إصداره. من الأمثلة على الأخطاء المحتملة في مهمة الإنترنت غير المتزامنة: "الشبكة غير متاحة"، "الخادم غير موجود"، "تجاوز مهلة الانتظار"، ...
    • يمكن للكود الرئيسي الذي أطلق مهمة غير متزامنة الاشتراك في الأحداث التي من المحتمل أن تصدرها هذه المهمة. وعندما يتم إصدار أحد هذه الأحداث، يتم إخطار الكود الرئيسي بذلك ويمكنه تشغيل وظيفة معينة مخصصة لمعالجة الحدث. تتلقى هذه الوظيفة كمعلمة البيانات التي ربطتها المهمة غير المتزامنة بالحدث الصادر؛

    11.2. نص برمجي [async-02]

    في هذا البرنامج النصي، ستصدر الوظيفة غير المتزامنة [setTimeout] أحداثًا لإرسال البيانات إلى الرموز التي اشتركت في هذه الأحداث.

    يتطلب الوصول إلى أحداث [node.js] مكتبات إضافية. نختار المكتبة [events] التي نقوم بتثبيتها مع [npm]:

    النص البرمجي [async-02] هو التالي:

    
'use strict';

// يمكن للوظائف غير المتزامنة إرجاع نتيجة عن طريق إصدار حدث
// يمكن للكود الرئيسي استرداد هذه النتائج من خلال الاشتراك في الأحداث التي تم إرسالها

// الاستيرادات
import moment from 'moment';
import { sprintf } from 'sprintf-js';
import EventEmitter from 'events';

// بداية
const débutScript = moment(Date.now());
console.log("[début du script],", heure());
// مرسل أحداث
const eventEmitter = new EventEmitter();

// setTimeout يضبط مؤقتًا لمدة 1000 مللي ثانية (المعلمة الثانية) ويعيد على الفور رقم هذا المؤقت
// عندما ينتهي المؤقت من 1000 مللي ثانية، فإنه يرسل حدثًا يتم وضعه في قائمة انتظار وقت التشغيل
// عندما تتم معالجة الحدث بواسطة وقت التشغيل، يتم تنفيذ الدالة (المعلمة الأولى)
setTimeout(function () {
  // سيتم تنفيذ هذا الرمز عندما يصل المؤقت إلى القيمة 0
  console.log("[setTimeout, fin du timer d'1 s],", heure(débutScript));
  // يتم إرسال حدث للإشارة إلى توفر نتيجة
  eventEmitter.emit("timer1Success", { success: 4 });
  // يتم إرسال حدث آخر للإشارة إلى توفر نتيجة أخرى
  eventEmitter.emit("timer1Failure", { failure: 6 });
}, 1000)

// يتم الاشتراك في الحدث [timer1Success]
eventEmitter.on('timer1Success', (result) => {
  console.log(sprintf("la fonction asynchrone du timer a rendu le résultat [%j], %s, via l'événement [timer1Success]", result, heure(débutScript)));
});

// يتم الاشتراك في الحدث [timer1Failure]
eventEmitter.on('timer1Failure', (result) => {
  console.log(sprintf("la fonction asynchrone du timer a rendu le résultat [%j], %s, via l'événement [timer1Failure]", result, heure(débutScript)));
});

// سيتم عرضه قبل رسائل الأحداث الصادرة عن الوظيفة المرتبطة بـ [timer1]
console.log("[fin du code principal du script],", heure(débutScript));

// أداة عرض الوقت والمدة
function heure(début) {
  // الوقت الحالي
  const now = moment(Date.now());
  // تنسيق الوقت
  let result = "heure=" + now.format("HH:mm:ss:SSS");
  // هل يجب حساب المدة؟
  if (début) {
    const durée = now - début;
    const milliseconds = durée % 1000;
    const seconds = Math.floor(durée / 1000);
    // تنسيق الوقت + المدة
    result = result + sprintf(", durée= %s seconde(s) et %s millisecondes", seconds, milliseconds);
  }
  // النتيجة
  return result;
}

    • السطر 9، يتم استيراد الفئة [EventEmitter] من المكتبة [events]. هذه ميزة جديدة: لم نكن حتى الآن نستورد سوى الكائنات الحرفية والوظائف؛
    • السطر 15: يتم إنشاء مُصدر أحداث [node.js] عن طريق إنشاء مثيل للفئة [EventEmitter] باستخدام الكلمة الرئيسية [new]؛
    • الأسطر 20-27: الدالة غير المتزامنة [setTimeout]. ستصدر هذه الدالة حدثين عند تنفيذها:
      • السطر 24، الحدث [timer1Success] مع القيمة المرتبطة به {success : 4}؛
      • السطر 26، الحدث [timer1Failure] مع قيمة مرتبطة به هي الكائن {failure : 6}؛
      • يمكن للدالة غير المتزامنة إصدار أي عدد تريده من الأحداث. ذكرنا سابقًا أنها غالبًا ما تصدر أحد الحدثين [success, failure]، وليس كليهما كما هو الحال هنا؛
    • السطر 20: يتم تنفيذ [setTimeout] على الفور: يتم ضبط مؤقت ويتم إرجاع رقمه إلى الكود المستدعي. سيتم إصدار الأحداث لاحقًا، هنا بعد ثانية واحدة؛
    • إرسال الأحداث لا فائدة منه إذا لم يكن هناك أي كود لاستغلالها عند حدوثها. لهذا السبب يجب أن يشترك الكود الرئيسي في الحدثين [timer1Success, timer1Failure] إذا أراد إدارتهما، ولا سيما استرداد البيانات المرتبطة بهذين الحدثين؛
    • الأسطر 30-32: يشترك الكود الرئيسي في الحدث [timer1Success]. عندما يعالج منفذ أحداث [node.js] هذا الحدث، فإنه سيستدعي الدالة التي تمثل المعلمة الثانية لطريقة [eventEmitter.on]، ممرراً إليها البيانات (المسماة هنا [result]) المرتبطة بالحدث [timer1Success]؛
    • السطر 31: ستعرض وظيفة معالجة الحدث jSON للبيانات المرتبطة بالحدث بالإضافة إلى الوقت الحالي؛
    • الأسطر 35-37: باستخدام كود مشابه، يشترك الكود الرئيسي في الحدث [timer1Failure]؛
    • لا يؤدي الاشتراك في حدث ما (المعلمة الأولى) إلى تنفيذ كود الدالة [callback] (المعلمة الثانية) على الفور. ولن يتم تنفيذ هذه الدالة إلا بعد وقوع الحدث؛
    • السطر 40: انتهى كود البرنامج النصي الرئيسي ولكن لم ينته البرنامج النصي نفسه لأن الكود الرئيسي أطلق مهمة غير متزامنة. لن ينتهي البرنامج النصي الشامل إلا بعد انتهاء هذه المهمة غير المتزامنة؛

    11.3. النص البرمجي [async-03]

    يُظهر البرنامج النصي التالي جانبًا آخر من حلقة الأحداث لـ [node.js]:

    • تقوم الحلقة بتنفيذ الأحداث واحدًا تلو الآخر، عادةً حسب ترتيب وصولها. بعض OS تمنح الأولوية للأحداث التي يتم معالجتها بعد ذلك حسب الأولوية وليس حسب ترتيب الوصول؛
    • لا تنفذ الحلقة سوى حدث واحد في كل مرة. ولا تتم معالجة الحدث التالي إلا بعد الانتهاء من معالجة الحدث السابق. في نظام الأحداث، يجب إذن تجنب كتابة كود يستحوذ على المعالج لفترة طويلة، لأن الأحداث في هذه الحالة لا تتم معالجتها عند حدوثها، بل في وقت لاحق عندما تصل إليها حلقة الأحداث. ونحصل عندئذ على تطبيق "غير تفاعلي" إلى حد ما؛

// يمكن للكود الرئيسي استرداد هذه النتائج من خلال الاشتراك في الأحداث التي تم إرسالها

    11.4. البرنامج النصي [async-04]

    يُظهر البرنامج النصي [async-04] آلية أخرى، تُسمى [Promise]، وهي وعد بالنتيجة. تتيح هذه الآلية تجنب إدارة أحداث [node.js] بشكل صريح. يتم ذلك ضمنيًا، وبذلك يمكن للمطور تجاهل وجود هذه الأحداث. ومع ذلك، فإن فهمها سيسمح له بفهم أفضل لكيفية عمل [Promise] التي تبدو معقدة للوهلة الأولى.

    النوع [Promise] هو فئة جافا سكريبت. يقبل منشئها كمعلمة دالة غير متزامنة تمرر إليها معلمتين يُطلق عليهما تقليديًا [resolve] و [reject]. يمكن أن تحملان اسمًا آخر؛

    • يقوم منشئ [Promise] بأمرين:
      • إنه ينشئ حدثًا لبدء تنفيذ الدالة [function(resolve, reject)] التي تم تمريرها إليه كمعلمة، لكنه لا ينتظر نتيجتها ويقوم على الفور بإرجاع كائن [Promise] إلى الكود المستدعي. وقد يكون لهذا الكائن أربع حالات:
        • [pending]: العملية غير المتزامنة التي أدت إلى ظهور [Promise] لم تنتهِ بعد؛
        • [fulfilled]: انتهت العملية غير المتزامنة التي أنتجت [Promise] بنجاح؛
        • [rejected]: انتهت العملية غير المتزامنة التي أنتجت [Promise] بالفشل؛
        • [settled]: انتهت العملية غير المتزامنة التي أنتجت [Promise]؛

    عندما يعرض المُنشئ نتيجته، يكون الكائن [Promise] الذي تم إنشاؤه في الحالة [pending]، في انتظار نتائج الدالة غير المتزامنة؛

        • تشير المهمة غير المتزامنة إلى النجاح بواسطة [resolve(result)]. وهذا يعادل وضع حدث في حلقة أحداث [node.js]، يمكن تسميته [resolved] مع [result] كبيانات مرتبطة؛
        • تشير المهمة غير المتزامنة إلى فشل بواسطة [reject(error)]. وهذا يعادل وضع حدث يمكن تسميته [rejected] في حلقة أحداث [node.js]، مع [error] كبيانات مرتبطة به، وعادةً ما يكون كائنًا يوضح تفاصيل الخطأ الذي حدث؛
        • لذلك يجب أن يشترك الكود المستدعي في هذين الحدثين ليتم إخطاره بتوفر نتيجة الدالة غير المتزامنة؛

    بعد الانتهاء من تنفيذ المهمة غير المتزامنة المُغلفة في [Promise]، يتغير حالة الكائن [promise] الذي تم إنشاؤه بواسطة المُنشئ [Promise(…)]:

    • يؤدي الحدث [resolved] إلى تغيير حالته من [pending] إلى [resolved]؛
    • يؤدي الحدث [rejected] إلى انتقاله من الحالة [pending] إلى [rejected]؛

    يتم الاشتراك في الأحداث [resolved] و [rejected] للمهمة غير المتزامنة باستخدام طرق من الفئة [Promise] بالصيغة التالية:

    promise.then(f1).catch(f2).finally(f3) ;

    حيث:

    • f1 هي دالة يتم تنفيذها عندما يتغير حالة [promise] من [pending] إلى [resolved]، أي عندما تنجح المهمة غير المتزامنة في إنجاز عملها. وهي تتلقى كمعلمة القيمة [result]، التي يتم إرسالها بواسطة الأمر [resolve(result)] الخاص بالمهمة غير المتزامنة؛
    • f2 هي دالة يتم تنفيذها عندما يتغير حالة [promise] من [pending] إلى [rejected]، أي عندما تفشل المهمة غير المتزامنة في إنجاز عملها. وهي تتلقى كمعلمة القيمة [error]، التي يتم تمريرها بواسطة الأمر [reject(errror)] الخاص بالمهمة غير المتزامنة؛
    • f3 هي دالة يتم تنفيذها بعد تنفيذ الطرق [then] أو [catch]، وبالتالي يتم تنفيذها دائمًا. ولا تتلقى أي معلمة؛

    تخفي هذه الصيغة تمامًا الأحداث التي يتم الاشتراك فيها. ومع ذلك، فهي اشتراك، ومثل الاشتراك في المثال السابق، لا تنفذ الدالة [f1, f2, f3] على الفور. سيتم تنفيذ هذه الدالة أو عدم تنفيذها عندما يحدث أحد الأحداث [resolved, rejected] التي تم الاشتراك فيها.

    11.6. نص برمجي [async-06]

    يوضح هذا البرنامج النصي الجديد كيف أن الاستخدام المشترك للكلمات الرئيسية [async / await] يتيح الحصول على كود غير متزامن يشبه الكود المتزامن. يتم إخفاء إدارة الأحداث تمامًا، مما يسهل فهم الكود.

    نستأنف المثال السابق بإجراء التعديلات التالية عليه:

    • نضيف دالة غير متزامنة ثالثة [async03] والتي تعيد النتيجة باستخدام الطريقة [Promise.reject] التي تشير بالتالي إلى حلقة الأحداث بأنها "فشلت" في أداء مهمتها؛
    • نقوم بتنفيذ الوظائف غير المتزامنة الثلاث [async01, async02, async03] بالتسلسل. في المثال السابق، كنا قد نفذنا الوظائف غير المتزامنة [async01, async02] بالتوازي؛
    • قبل ظهور الكلمات الرئيسية [async/await]، كان التنفيذ التسلسلي للأعمال غير المتزامنة يتم باستخدام [Promise] المتداخلة مع بعضها البعض. وبمجرد وجود عدة إجراءات غير متزامنة لتنفيذها بهذه الطريقة، كان عدد الوعود يزداد تبعًا لذلك وكان الكود يصبح أقل قابلية للقراءة؛

// أداة مساعدة
function heure(début) {
  // الوقت الحالي
  const now = moment(Date.now());
  // تنسيق الوقت
  let result = "heure=" + now.format("HH:mm:ss:SSS");
  if (début) {
    const durée = now - début;
    const milliseconds = durée % 1000;
    const seconds = Math.floor(durée / 1000);
    // تنسيق المدة
    result = result + sprintf(", durée= %s seconde(s) et %s millisecondes", seconds, milliseconds);
  }
  // النتيجة
  return result;
}
